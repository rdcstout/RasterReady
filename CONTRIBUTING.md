# Contributing to RasterReady

Useful bug reports, focused fixes, documentation and accessibility improvements are welcome. Check existing issues and coordinate substantial features, dependencies, architecture or default changes before starting. Small fixes can be proposed directly. Acceptance, merging and release timing remain with the maintainer.

Report an ordinary bug with the version/commit, OS and processor, steps, expected and actual behavior, and a small sanitized image when needed. Remove personal images, embedded location, credentials and identifying paths. Use [SECURITY.md](SECURITY.md) for suspected vulnerabilities; do not disclose them publicly.

Follow [DEVELOPMENT.md](DEVELOPMENT.md) for setup and [validation](DEVELOPMENT.md#validation). Preserve originals, direct Downloads/project output, metadata removal, orientation/color handling and responsive batches. Keep changes focused, use assets you have rights to contribute, and document dependencies and licenses. Contributions to RasterReady's own code use the [MIT License](LICENSE); preserve third-party license notices. Do not commit settings, secrets, fixtures containing personal data, caches or installers.

In a PR, explain the user-visible problem and result, include relevant test results, identify untested platforms, and attach sanitized screenshots for UI changes. Add a focused regression test for a reproducible bug where practical. A build alone does not prove packaged usability. The [automated-checks section](DEVELOPMENT.md#automated-checks) describes the current CI state.

Update a branch for substantive changes, review feedback or conflicts; do not push just to catch up with main or repeatedly rerun unchanged checks. Preserve others' work and coordinate before rewriting shared history. Contributors must not merge or publish releases without authorization. Review and support are best effort, without a guaranteed response schedule.
